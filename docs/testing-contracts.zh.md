# 测试边界与契约校验

<b>中文</b> | <a href="testing-contracts.md">English</a> · <a href="README.md">返回文档索引</a>

`mindie-agent-codex` 采用分层确定性验证流水线：先通过 `tests/preflight.py` 完成环境与锁定依赖预检，再运行标准 `unittest` 测试套件。CI 会依次完成 Python 字节码编译、锁定 Git 提交核验、安装与更新探针，以及进程归属、Unicode 路径与服务生命周期契约测试。

---

## 1. 多维契约测试矩阵

| 测试边界 | 具体验证内容 | 独立于本项的外部边界 |
|---|---|---|
| **锁定依赖探针** | 在未修改的锁定依赖包上运行生产探针；通过负向对照验证缺失接口会被立即拒绝 | 真实大模型推理质量 |
| **发布兼容性校验** | 验证当前运行时生成的知识包可通过 `product-contract.json` 指定的独立校验器；篡改正文或非法格式会被拒绝 | 远端 GitHub Bot 真实鉴权与合入 |
| **Windows 进程归属** | 基于真实子进程、继承管道、主进程退出与外部看门狗验证 Windows Job Object 回收 | POSIX 进程组（`killpg`）语义 |
| **授权配置并发锁** | 两个写入进程在真实操作系统文件锁上竞争，校验锁获取屏障与内容完整性 | 内存级 Mock 锁顺序 |
| **服务平滑交接** | 验证认证空闲确认、消费锁释放、旧服务自然退出与新服务启动就绪 | 完整端到端业务会话体验 |
| **UTF-8 与中文路径** | 在包含中文/Unicode 的目录路径及 Windows `cp1252` 默认编码环境下验证完整安装、回读与 MCP 往返 | 仅英文 ASCII 路径 |
| **持久防重放历史** | 验证跨 4096 条边界的 SQLite 历史记录写入，以及重启后对最旧/最新重复事件的确切拒绝 | 极限吞吐性能压测 |

---

## 2. 测试设计准则与跨组件互操作

- **最小外部替身原则**：仅在最外层边界使用夹具（例如向真实 Python 解释器传入测试脚本参数，而非伪造可执行解释器）。缺失必要测试依赖时直接报错退出，绝不将缺失依赖静默跳过当作测试通过。
- **独立发布校验器（`test_publication_compatibility.py`）**：根据 `product-contract.json` 中锁定的官方声明，在独立虚拟环境中安装对应版本的校验器，验证当前运行时生成的知识包完全符合公开交换格式，且全程不把知识包内容当作代码执行。
- **跨平台真实机制验证**：锁版本比对严格校验 Git Blob 哈希与 VCS 提交回执（仅消除 Windows Git 检出时的 CRLF 换行差异）。Windows Job Object 与 POSIX 进程组/FIFO 等平台原生机制在各自对应的操作系统 CI 上真实运行，不互相冒充。

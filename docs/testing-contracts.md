# Test Boundaries & Contract Verification

<a href="testing-contracts.zh.md">中文</a> | <b>English</b> · <a href="README.en.md">Documentation Index</a>

`mindie-agent-codex` uses a layered verification pipeline starting with `tests/preflight.py` followed by the standard `unittest` suite. In CI, every Python file is compiled first, pinned Git commits are verified, and native ownership, Unicode, and service-lifecycle contracts run before the full component test suite.

---

## 1. Contract Test Matrix

| Verification Boundary | What Is Verified | What Remains Separate |
|---|---|---|
| **Locked Dependency Probe** | Production probes run against the unmodified locked packages; negative controls verify that missing consumed methods are rejected | Live model reasoning quality |
| **Publication Compatibility** | Knowledge packages generated by the pinned runtime pass the independent validator specified in `product-contract.json`; tampered bodies or schemas are rejected | Live GitHub Bot authentication & merge |
| **Windows Process Ownership** | Real child processes, inherited pipes, leader exit, timeout, and external watchdog verification via Windows Job Objects | POSIX process-group (`killpg`) semantics |
| **Consent Serialization** | Concurrent writers contend on a real OS file lock with observable acquisition barriers | Mocked in-memory lock ordering |
| **Service Handoff** | Authenticated idle acknowledgement, consumer lock release, clean exit, and replacement service startup | Full end-to-end user session workflow |
| **UTF-8 & Unicode Paths** | Full setup, Core readback, and MCP round-trip under Unicode directory paths and Windows `cp1252` environments | ASCII-only paths |
| **Durable Replay History** | SQLite replay history across the 4096-entry boundary and deterministic duplicate rejection across restarts | Unbounded throughput benchmarking |

---

## 2. Testing Principles & Interoperability

- **Minimal External Mocking**: Fixtures are injected only at the outermost boundary (for example, passing a synthetic script argument to a real Python interpreter rather than mocking the interpreter itself). Missing dependencies fail explicitly rather than silently skipping tests.
- **Independent Publication Validator (`test_publication_compatibility.py`)**: Installs the exact trusted validator commit declared in `product-contract.json` into a separate virtual environment and verifies that packages produced by the current runtime pass validation without executing untrusted content.
- **Cross-Platform Fidelity**: Pin checks verify exact Git blob hashes and VCS commit receipts while normalizing only Git's CRLF checkout behavior on Windows. Platform-specific mechanisms (Windows Job Objects vs. POSIX process groups and FIFOs) are tested explicitly on their respective OS runners.

# 显式历史会话导入

<b>中文</b> | <a href="history-import.md">English</a> · <a href="README.md">返回文档索引</a>

`history-import` 命令允许你将显式指定的历史 Codex JSONL 会话文件导入到社区经验贡献流水线中。日常会话使用、`Stop` Hook、自动更新检查与知识同步**绝不会**自动扫描或偷偷导入任何历史会话文件。

---

## 1. 命令用法与权限核验

通过当前发行版入口调用 `bridge history-import`，并通过 `--source` 指定一个或多个本地 JSONL 会话文件的绝对路径（Windows 下可将 `python3` 替换为 `python`）：

```sh
python3 <PLUGIN_DATA>/releases/0.0.1/entry.py bridge history-import \
  --source /absolute/path/to/rollout.jsonl
```

- **严格按指定文件读取**：无默认路径、无目录监听、无定时扫描；会话正文内的任何指令均被视为纯文本数据，无权触发其他文件导入。
- **复用已保存的贡献授权**：导入前会自动校验当前会话与源历史会话的工作目录是否均处于用户已批准的公开贡献项目范围内，不会重复弹窗询问，也不会重新激活历史会话。

---

## 2. 增量脱敏与断点续传

- **完整复用实时脱敏管线**：按分页读取源文件至初始字节边界，完整复用实时 `Stop` 采集的确定性公开消息筛选、Gitleaks `8.30.1` 本地脱敏与不可变 Markdown 分块落盘流程（原始 JSONL 仍留在 Codex 目录中不被修改）。
- **分页容错与防残缺发布**：在源文件全部页面完成准入前，持久化标记会阻止未完成快照对外发布；若中间某页失败，前面已处理的分块会保留在本地支持断点续传，回执会如实报告 `failed` 而非伪造全部导入成功。
- **重复导入自动去重**：对同一文件再次执行导入时，会核对已消费的前缀并仅导入新增对话内容；若文件未发生变化，不会生成重复分块，也不会产生任何额外的模型调用。

---

## 3. 结构化回执与显式重试

- **分阶段清晰回执**：返回的 JSON 回执明确区分本地准入状态（`imported`、`extended`、`unchanged`、`empty` 或 `failed`）、分块索引状态与待发布状态。
- **显式重试索引（`--retry-summary`）**：若生成导航索引的小模型调用失败或结果不确定，后台绝不会自动发起重复计费调用。如需在排查后显式重试，可在命令中附加 `--retry-summary` 参数（历史已发生的 Token 用量仍完整保留在账本中）。

# 故障诊断与取消边界

<b>中文</b> | <a href="failure-diagnostics.md">English</a> · <a href="README.md">返回文档索引</a>

遵循 [MindIE Agent 工程设计原则](https://github.com/mindie-agent/mindie-agent/blob/main/docs/design-principles.md)中“工具可观察、可定位，禁止隐藏错误”的要求，`mindie-agent-codex` 提供纯只读状态诊断、本地子进程树精准取消回收，以及与远端昇腾后台作业的清晰边界划分。

---

## 1. 纯只读状态诊断（`bridge status`）

- **精准区分故障类型**：`bridge.py status` 明确区分“配置不存在”、“配置文件损坏/格式非法”、“更新锁被占用”以及“运行时启动失败”。已存在但损坏的配置文件会直接作为诊断错误报告，绝不会当成“首次安装”而触发初始化向导覆盖原文件。
- **按任务隔离的诊断快照**：基于原生 `CODEX_THREAD_ID`，`status` 返回客观的控制面事实状态（`configured`、`knowledge_enabled`、当前启动阶段、配置/存储/后台服务健康度、`this_session` 手动激活租约状态、诊断失败计数，以及关联的最近 5 次采集与贡献批次），不包含任何首次引导提示字段（`first_use`、`next`、`recovery`）；无任务身份时不返回其他任务的记录。
- **严格只读、零副作用**：`status` 在 5 秒预算内完成读取，绝不隐式绑定任务、清零失败计数器、拉起后台服务或重放失败任务。若外部 GitHub PR 发布结果不确定，必须在显式执行 `recover` 重试前先完成状态对账。

---

## 2. 本地调用取消与远端昇腾持久作业分离

- **安全的远端异常分类**：远端操作异常返回固定的安全错误分类、投递确定性状态以及已存在的远端作业引用（Job ID），自动剔除未脱敏的原始标准错误输出。
- **本地进程清理 vs 远端作业生命周期**：打断前台工具调用或遇到标准输入关闭（`EOF`）时，插件会立即清理本次调用所拥有的本地辅助进程与 SSH 子进程树；但这**并不代表**远端昇腾服务器上通过 `remote-dev` 启动的持久编译或测试作业已经停止。远端持久作业保留其独立作业 ID，供后续显式查询或终止。
- **远端开发与知识服务解耦**：即使本地知识库服务异常，原生 Shell/SSH 以及独立配置的 `mindie-remote-dev` 依然保持正常可用。

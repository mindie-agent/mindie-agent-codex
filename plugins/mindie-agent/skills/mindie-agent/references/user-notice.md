# MindIE Agent 用户须知

本页说明已开启社区贡献时的数据处理方式，供使用前及使用中查阅。阅读本页不增加确认、授权或逐次发布操作；已有的贡献选择和项目范围继续生效。

## 会共享什么

在已启用 MindIE、允许贡献且处于配置范围内的任务中，插件保留**完整的可见用户消息、助手进展说明和最终答复**，在本机机械脱敏后，按原顺序保存为 Markdown 任务包，并自动向配置的公开 GitHub 仓库提交 PR。失败尝试、未完成工作、错误判断和后续修正也会保留；正文不是只包含最终结论的人工精选报告。

隐藏推理、系统/开发者指令和工具调用及返回值不在这条采集路径中。助手在可见答复中转述的命令、结果或其他内容仍属于可见材料。正文中的“已验证”是原会话的陈述，不等于知识库独立核验了原始工具证据。

历史会话只有在明确选定来源并要求导入时才处理。普通启用、同步和检索不会自动发现、导入其他历史任务。

## 脱敏的范围

程序使用固定扫描器和隐私规则识别凭据、地址、个人路径等已定义模式。扫描失败会阻止相关材料继续发布，不会用未检查的材料代替。**规则无法判断全部商业机密、内部计划或自然语言中的保密含义。** 不适合公开的任务应排除在贡献范围之外，或关闭社区贡献。

标题、块摘要和任务导航由当前适配器使用已有模型生成，不能改写完整正文。本机编排不代表离线模型：使用云端 Harness 时，已经过规则脱敏的索引输入仍会交给该模型提供商。普通消费者检索、阅读和同步不调用模型。

## 公开历史与参考性质

GitHub PR、提交及版本历史是公开发布的一部分。从当前知识库撤回材料，不等于已从既有 Git 历史、分叉、缓存或第三方副本中删除全部副本。

检索命中、模型摘要、PR 审阅与合并都不证明技术结论正确。引用表示来源关系，不代表一次独立实验。使用时结合当前环境、适用条件、失败记录和后续修正判断；不要求每次使用重新跑实验或提交反馈。

## 关闭或调整贡献

可通过原有 MindIE 入口调整贡献选择和项目范围。关闭贡献会停止新采集和未发工作，按现有规则取消受管处理；不会自动删除已有私有材料、已发布 PR 或公开 Git 历史。重新开启只处理新获准材料，不自动补录关闭期间的对话。知识阅读、同步和通用远端工具独立可用。

状态分别报告本地材料、索引、提交与同步结果。保存正文不等于已发布；提交结果不确定时先核对原操作，不自动重复写入。

## 统一贡献开关与故障上报

社区知识贡献与自动工具故障上报共用 `<profile>/.mindie/mindie-consent.json` 中的同一个持久化开关：
- **统一开启与关闭**：显式开启社区贡献（`contribute`）会同时授权配置范围内的知识 PR 与脱敏产品故障 Issue，并启动后台上报服务；关闭贡献（`disabled`）会同时停止两条路径的后续外发，待发送队列在发送前会重新核验授权并终止外发，且不会补报关闭期间产生的故障。已有的 `disabled`、`later` 与 `read-only` 选择在版本升级后保持关闭。
- **最小化脱敏载荷**：故障上报仅包含静态产品阶段、错误分类与已安装版本号，不包含任务对话、命令、文件路径、环境变量、凭据或原始异常堆栈。
- **旧版配置升级说明**：若旧版配置仅包含早期的知识 `contribute` 记录而缺少统一授权版本（`choice_revision`），升级后不会自动获得故障上传权限，状态会显示 `needs_choice`；待用户重新显式确认一次后，后台 reporter 才会启动。
- **清晰的状态区分**：系统在状态回执中严格区分**本地授权配置已写入**、**后台 reporter 服务运行中**与**外部 GitHub Issue/PR 已实际创建**三种状态，绝不将本地配置保存直接报告为远端已送达。

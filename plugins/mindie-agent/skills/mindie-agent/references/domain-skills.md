# Domain Tooling, Graded Knowledge & Long-Horizon Execution

The `mindie-remote-dev` MCP tools are available on demand in any session without activating MindIE Agent. Pass explicit host, port, user, container, and working directory parameters, and poll or manage the session's returned job handles.

## 1. Graded Knowledge (`L1–L4`), Reference Identity & `knowledge_distill`

- **Purpose Tier vs. Evidence Strength**:
  - `tier` (`L1` axioms & measurement probes, `L2` troubleshooting SOPs, `L3` convergence workflows, `L4` exploration mutators) describes how a unit is used.
  - `evidence_strength` (`hardware_spec` | `reproduced_empirical` | `single_observation` | `hypothesis`) and `provenance` describe how strongly it is supported.
- **`knowledge_query` (`graded-bm25`)**:
  - Parameters: `query`, optional `domain` (default domain or a registered `domain_configs` route such as `"vllm-ascend"` or `"operators"`), `limit` (`1..20`), `conditions`, `continuation`, `domain_path`, `token_budget` (`1..16000`, default `800`), `include_unknown` (default `false`), and `include_archived` (default `false`).
  - Returns bounded navigation `cards`, deduplicated `foundation_cards` (matched `L1` premises), compatible `results[]`, and `usage`.
  - Each item includes `id` (`unit-...`), revision-bound `ref` (`mindie://<domain>/units/<id>@<integer revision>`), `unit_ref` (`mindie://<domain>/units/<id>`), `feedback_ref` (equal to `ref` for graded units), `revision`, `match_status` (`matched` | `mismatched` | `condition_unknown`), `missing_conditions`, `tier`, `category`, `evidence_strength`, `domain_path`, `conditions`, `provenance`, `excerpt`, and `inherited_rules`.
- **`knowledge_explain` & `knowledge_feedback` Routing**:
  - Pass revision-bound `ref` URIs (`mindie://<domain>/units/<id>@<integer revision>`) to `knowledge_explain(refs=[...], conditions=..., known_refs=..., token_budget=4096)` and `feedback_ref` to `knowledge_feedback`. Both route by the `mindie://<domain>/...` URI authority (do not pass bare IDs or mix domains in one batch).
  - `knowledge_explain(refs=[...])` returns complete untruncated bodies in `units`, shared prerequisites once in topological order in `requires`, and any exclusions in `unresolved` (`condition_unknown`, `condition_mismatch`, `budget_excluded`, `removed_or_superseded`, `not_found`). `known_refs` should list only exact `id@revision` refs currently visible in active context.
  - `knowledge_feedback` records four-stage usage events (`discovered` | `loaded` | `applied` | `evaluated`, with `run_id`, optional `step_id`, and `outcome="supported"|"refuted"|"inconclusive"`) and/or an optional `rating="up"|"down"`. When citing units in reports or ledgers, record `unit_id` and integer `revision`.
- **Three-Valued `conditions` (`matched` | `mismatched` | `condition_unknown`)**:
  - Query evaluates each unit's declared condition keys (`soc`, `cann`, `driver`, `framework`, `repository`, `revision`, `workload_scope`, `dtype`, `input_shape`, etc.). If a required premise or observed fact is missing or `"unknown"`, status is `condition_unknown`; probe the missing fact before applying the unit.
- **Selected-Evidence Distillation (`knowledge_distill`)**:
  - `knowledge_distill(inputs, task_state, domain=..., related_refs=[...], proposal=...)` distills authorized evidence (`inputs` items with `kind`, `outcome`, `source_locator`, `content`, `evidence_refs`, optional `repetitions >= 1`) at `task_state="verified_milestone"` or `"completed"`.
  - `hardware_spec` requires a `hardware_spec` source; `reproduced_empirical` requires `outcome == "verified"` with `repetitions >= 2`; `L4` requires a verified `mindie-bench-ablation/1` receipt. `observed` or fault/build evidence (`compile_failed`, `infra_failed`, `measurement_invalid`) distills into `single_observation` or `hypothesis`.
  - Pass `related_refs` for delta comparison (`revise`/`merge`/`supersede` over duplicates), or pass a `mindie-distill-decision/1` `proposal` for deterministic validation and application (`model_calls=0`).

## 2. Stagnation Gate & De-Biased Exploration

- When `assess_stagnation` reports three consecutive unimproved attempts on the same L3 branch (deduplicated by `run_id`, with no new fact or divergent layer), stop repeating that branch.
- Call `knowledge_query(query=..., mode="explore", native_subcontext=True, ledger_entries=[...], bottleneck_summary={...}, goal=...)` and inspect `exploration_context.subagent_fact_pack` (`schema_version == "mindie-rsi-subagent-pack/1"` and `stripped_l3_ids`).
- Spawn a fresh native subagent seeded only with `subagent_fact_pack.prompt_brief` (L1 hard constraints + L2 bottleneck + L4 mutators + `conditional_avoid`, with prior L3 trajectory stripped).

## 3. Long-Horizon Continuation Ledger (`PROGRESS.md` + `experiment-ledger.jsonl`)

- **Launch-Time `run_id` Registration**: `coordinator` assigns `run_id` (`run_id == execution_id`) at submission. Immediately upon launching a managed run or background job, atomically update `PROGRESS.md` (`os.replace`) to record `{run_id, job_id, slot_id, host_endpoint, manifest_path, started_at}` under `in_flight_runs`, along with the task goal, current `git_commit`/`diff_digest`, verified baseline `run_id`, best verified candidate `run_id`, active hypothesis, and key `conditional_avoid` refs.
- **Recovery-First-Query**: After any context compaction, interruption, or session resume, read `PROGRESS.md` `in_flight_runs` first and query `TaskClient.observe(run_id=...)` or `remote_job_status(job_id=...)` before submitting new work.
- **Single-Writer `experiment-ledger.jsonl` & Sequential Pruning**:
  - Append one JSON record per experiment: `{"task_id", "exp_id", "run_ids": [...], "hypothesis", "factors": [...], "factor_roles": {"<f>": "performance|correctness_required|dependency|inseparable_group"}, "unit_refs": [{"unit_id", "revision"}], "receipt_refs": {"manifest", "profile", "ablation"}, "run_status", "judgment": "supported|refuted|inconclusive", "scope_conditions": {"soc", "cann", "dtype", "shape_family"}, "conditional_avoid": "...", "supersedes_exp_id": null}`.
  - Compile errors, SSH drops, or invalid measurement windows are `inconclusive` (not `refuted`).
- **Ledger Helper (`experiment_ledger.py`) on top of MindIE Bench**: judgment, the ledger line format and `PROGRESS.md` come from MindIE Bench (`mindie_bench.runner.rsi_explorer.evaluate_rsi_candidate_gates` and `append_ledger_and_render_progress`; verdicts `supported | subtarget_valid | refuted | inconclusive`). The helper only adds what Bench lacks: a source fingerprint, a raw paired-trial check, and a pre-device duplicate/budget gate. Run it with the runtime Python; each command prints one JSON object.
  - `python -I <runtime_scripts>/experiment_ledger.py fingerprint <repo>` returns `source_digest` over Git `HEAD`, the tracked diff, untracked file contents and submodule commits. Fingerprint both the baseline and the candidate checkout. Untracked files above 512 MiB are identified by size only and listed in `unhashed_large_files`; keep profiling dumps outside the checkout or in `.gitignore`.
  - Before submitting a candidate to a device, run `experiment_ledger.py gate --ledger experiment-ledger.jsonl --task-id <id> --source-digest <digest> [--scope '<conditions JSON>'] [--max-runs N] [--max-card-seconds S]`. Exit code `3` means `duplicate` (this exact source already has a live `supported`/`subtarget_valid`/`refuted` record under the same `conditions`, where an omitted scope equals `{}`; reuse `prior`) or `budget_exhausted`; do not submit. An `inconclusive` record never blocks a retry. Spend counts distinct `run_ids`, and a `supersedes_exp_id` revision of the same runs replaces their `card_seconds` instead of adding them. Take budgets from the user or task; the helper has none of its own.
  - After the runs, pipe `{"repetitions", "direction": "maximize|minimize", "target_speedup", "baseline": [{"status", "metric"}], "candidate": [...], "correctness": "passed|failed", "compile_ok", "run_status", "baseline_source_digest", "source_digest", "scope_conditions", "run_ids", "exp_id", "hypothesis", "factors"}` (optional `noise_margin`, `ablation_retained`, `ablation_receipt`, `hidden_input_summary`) to `experiment_ledger.py judge`. It checks the raw trials first: missing or non-`completed` trials, an unbuilt candidate, an execution-failure `run_status`, unverified correctness and a missing or unchanged fingerprint set `measurement_passed=false`, so Bench returns `inconclusive` (missing evidence outranks a failed correctness check). Then Bench judges the median paired ratio: a gain below the target is `subtarget_valid`, a ratio within `1 ± noise_margin` is `inconclusive` (`speedup_within_noise`), several `factors` without an ablation receipt are `inconclusive` (`ablation_pending`), a correctness failure or a regression is `refuted` with a scoped `conditional_avoid`.
  - Record the Bench entry plus `task_id`, `exp_id`, `run_ids`, `source_digest` (and optional `card_seconds`) with `experiment_ledger.py append --ledger experiment-ledger.jsonl [--progress PROGRESS.md] [--goal "..."]`. It writes through `append_ledger_and_render_progress`, which rewrites `PROGRESS.md`, and rejects a missing fingerprint, an execution failure that is not `inconclusive`, and a reused `exp_id` unless `supersedes_exp_id` is set.
  - **Contract C4 (`candidate_for_sequential_pruning` -> RETAIN)**: Leave-One-Out `delta <= tolerance` only marks a factor `candidate_for_sequential_pruning`. Treat `candidate_for_sequential_pruning` with `pruned_combination_verified == false` as **RETAIN**; only prune factors verified by sequential `pruning_runs` where the final combination passes both `correctness_verified` and `performance_verified` (`pruned_combination_verified == true`).

- **Resumable Optimization Loop (`rsi_loop.py`)**: for multi-round tuning, drive each round through `python -I <runtime_scripts>/rsi_loop.py` instead of tracking the order in prose. Each command prints one JSON object with the current `round`, `step`, knowledge `mode`, the `PROGRESS.md` path and a `guide` naming the tool to call.
  - `rsi_loop.py init --state rsi-loop.json --task-id <id> --ledger experiment-ledger.jsonl --baseline-repo <checkout> --direction maximize|minimize --repetitions N [--target-speedup X] [--max-rounds N] [--max-runs N] [--max-card-seconds S] [--progress PROGRESS.md] [--goal "..."]` fingerprints the baseline and starts round 1 at `profile`. `PROGRESS.md` defaults to the ledger directory. Take budgets from the user or task.
  - Every round is `profile` (`mindie_profiler` under a coordinator lease) -> `consult` (`knowledge_query` in the mode `next` names when knowledge is enabled and a gap remains; otherwise `unit_refs: []` with `skipped_reason`) -> `propose` (one hypothesis, optional `factors`; the loop fingerprints the checkout and runs the ledger `gate`, exit `3` = do not submit) -> `measure` (AB/BA runs through coordinator/remote-dev, `run_ids` in `PROGRESS.md`; the loop re-fingerprints, then `judge`s through Bench) -> `learn` (optional `distill` receipt and `note`; the loop appends the Bench entry and our fields, which rewrites `PROGRESS.md`).
  - Report each step with `rsi_loop.py complete <step> --state rsi-loop.json` (step evidence JSON on stdin). An out-of-order step is rejected; after any interruption or compaction run `rsi_loop.py next --state rsi-loop.json` and continue from the step it names.
  - A `supported` or `subtarget_valid` candidate becomes the new baseline; without a `distill` receipt it stays in `pending_distill`. A round that kept the baseline reuses its profile, so the next round starts at `consult`, and a candidate that shared the baseline checkout gets a `restore_hint` (prefer a separate `git worktree`). `assess_stagnation` runs once per live experiment; three unimproved rounds switch the next `consult` to `mode="explore"`. It finishes at `--max-rounds`, an exhausted budget, or `rsi_loop.py finish --reason ...`.

## 4. NPU Timing Mutual Exclusion & Profiler Discipline

- **CPU Pre-Compilation (`npu_count=0`)**: Confirmed device-free build or inspection steps may run concurrently using per-slot cache directories (`MINDIE_SLOT_ID`, `ASCEND_CACHE_PATH`, `TORCHINDUCTOR_CACHE_DIR`, `TRITON_CACHE_DIR`).
- **Exclusive Physical NPU Lease**: Any benchmark, attribution check, or `mindie_profiler` capture on the same physical NPU (or same Ascend A3 dual-Die package) must hold an exclusive `coordinator` lease and drain `/proc` process trees before the next run.
- **`mindie_profiler` Conventions**:
  - Pass explicit `--time-window START:END`, `--step-window STEP=START:END` / `--steps-file`, or `--full-range` (`--unit us|ns|ms`), plus explicit scene annotations (`--mode`, `--framework`, `--phase`, `--tp`, `--dp`, `--graph-mode`, `--clock-domain`, `--input-signature`).
  - `busy_union` and `kernel_sum` are non-additive (`host_gap = wall - busy_union`, `exposed_comm = comm_union - noncomm_union`), and `slowest_rank` is selected by wall `p50` across 7 semantic blocks (`Attention`, `MoE`, `Comm`, `Norm`, `Copy_Layout`, `Host_Gap`, `Unclassified`).
  - Keep `ideal_hardware_lower_bound_ms` (single-kernel Roofline bound), `model_predicted_ms`, and `measured_device_ms` distinct, and rely on explicit hardware throttle signal bits rather than a static `85°C` threshold.

# MindIE Agent (Unified Entry)

Use knowledge when relevant experience could help the current task, and remote
tools when remote files, commands, or jobs are needed. Ordinary business tasks
require no MindIE activation command, status check, extra user message, or
closing step. Once the user opts in during installation or setup, the saved
contribution choice and project scope govern automatic capture at session end
(`Stop`)—never ask for that choice again in each task, and users never need to
explicitly ask to save experience. Explicit disable and scope limits remain
authoritative.

## Core Tools in Everyday Tasks

- **Domain Knowledge (`mindie-knowledge` MCP — Graded `L1–L4`, Multi-Domain Routing & Three-Valued `conditions`)**:
  - `knowledge_query`: search the default or explicitly selected `domain` (`query`, optional `domain`, `limit` 1–20, `continuation`, plus graded parameters `domain_path`, `token_budget` 1–16000, `include_unknown`).
  - `knowledge_explain(ref)`: read query's readable `ref` (`mindie://<domain>/units/<id>@<integer revision>`) or `unit_ref` for a `graded_unit` (which also returns `feedback_ref`), or a task/block `ref` for legacy block navigation—routed by the `mindie://<domain>/...` URI authority (for graded units `ref` and `feedback_ref` share the same revision-bound URI value, whereas legacy material keeps `ref` and `feedback_ref` distinct; never pass a bare `id`).
  - `knowledge_feedback`: optionally record `up` or `down` by copying the exact returned `feedback_ref` (`mindie://<domain>/...`, routed by URI authority domain, including revision-bound `/units/<id>@<integer revision>` for graded units; never pass a bare `id`).
  - `knowledge_distill(inputs, task_state, domain=...)`: explicitly distill caller-selected, already-authorized evidence into local C5 graded units for the default or activated target `domain` at `task_state="verified_milestone"` or `"completed"` (`completed` or `verified_milestone` with `observed` or fault/environment/build evidence [`compile_failed` / `infra_failed` / `measurement_invalid`] is allowed and can yield `single_observation` or `hypothesis`, preserving its true strength without elevating unverified faults to `hardware_spec` or `reproduced_empirical`; `reproduced_empirical` requires repeated `verified` evidence and `L4` requires a valid ablation receipt). Only `task_state="in_flight"` (or all-`in_flight` / empty inputs) is a zero-call no-op, and a single-turn host `Stop` event is **not** task completion.
  - **Three-Valued `conditions` (`matched` | `mismatched` | `condition_unknown`) & Paired-Runtime Boundary**: Knowledge is reference material, never blind instructions. Graded units separate functional `tier` (`L1` axioms/probes, `L2` SOPs, `L3` convergence workflows, `L4` mutators) from `evidence_strength` (`hardware_spec`, `reproduced_empirical`, `single_observation`, `hypothesis`) and evaluate the unit's declared condition keys. `condition_unknown` occurs when either the unit's declared `required` premise or the caller's `observed` fact is `"unknown"`, missing/not supplied, or has an incomparable format, and `unknown == unknown` never matches (an absent requirement or `"any"` is unconstrained `matched`, and historical `required: "unknown"` is never backfilled by later machine versions)—never treat `condition_unknown` as a match; verify whichever fact is missing/unknown (e.g., source `repository`/`revision` for an `L2` source SOP, or runtime environment for an NPU rule). Graded query options, multi-domain routing, and `knowledge_distill` require the paired `mindie-knowledge 0.13.0` runtime. Graded Git publication (`mindie-publication-contract/2`), independent Feed sync, and revision-bound unit feedback use that runtime; check the selected feed revision and installed runtime identity separately when diagnosing a mismatch.
- **Remote Ascend NPU Development (`mindie-remote-dev` MCP) & Long-Horizon Execution**:
  - Available automatically on demand in every native task for remote files, commands, jobs, and artifacts without activating knowledge capture.
  - **Long-Horizon Continuation & Recovery**: Immediately when `coordinator` or `remote-dev` starts a managed run or job, atomically update `PROGRESS.md` to register its `run_id` (`run_id == execution_id`, never replaced) or `job_id`, `slot_id`, endpoint, and `Run Manifest` path under `in_flight_runs` before waiting or ending the turn. After any interruption, compaction, or resume, query `in_flight_runs` first and never blindly resubmit an active or uncertain run. Keep `Run Manifest` execution facts separate from condition-scoped hypothesis judgments in `experiment-ledger.jsonl`, and treat `candidate_for_sequential_pruning` with `pruned_combination_verified=false` as **RETAIN**.
  - **Pre-Compilation Parallelism, Physical NPU Timing Mutual Exclusion & Profiler Discipline**: CPU pre-compilation (`npu_count=0`) may run in parallel across isolated slot caches, whereas performance timing, Gate 3/4 checks, and `mindie_profiler` runs on the same physical NPU (or same A3 dual-Die package) require an exclusive `coordinator` lease. `mindie_profiler` accepts explicit unlabeled `--time-window START:END`, labeled `--step-window STEP=START:END`, or `--full-range` (never inferring steps from kernel rows), uses explicit scene/clock annotations (`uncertain` / `clock_domain_unknown` otherwise), keeps single-kernel roofline bounds separate from unverified external `msmodeling` predictions, and never infers thermal throttling from a static `85°C` threshold.
- **Diagnostics & Unified Contribution Switch**:
  - Natural capability results can include bounded `agent_diagnostics` references for the Agent. Preserve the actual business result and report only limitations relevant to the user's goal. Stop capture must never request another model turn or block task completion.
  - Community knowledge sharing and automatic tool fault reporting share a single persistent choice in `<adapter-config-directory>/mindie-consent.json`. Reuse a valid saved choice without another prompt. Only when the entry returns `needs_choice` for a legacy knowledge-only `contribute` choice, resolve it once through `/mindie-agent` using the user's explicit choice; do not ask separately for knowledge and fault reporting, or ask again in each task. Keep saved `disabled`, `read-only` and `later` choices without prompting. Always keep three states distinct: (1) local consent configuration saved, (2) background reporter worker running, and (3) external GitHub Issue/PR published.

The consent file is beside the active adapter configuration (`adapter_config.parent / "mindie-consent.json"`); use the installed entry to change the choice, never a guessed profile path.

## Graded Execution Loop (`L1` + `L2` Foundation → `L3` Hermes → `L4` RSI)

- **`L1` + `L2` Foundation Baseline**: Query with the **observed** `conditions` (`soc`, `cann`, `driver`, `framework`, `repository`/`revision`, `dtype`, `input_shape` or workload case, etc.) before choosing a fix; never guess a condition to force a match. A matched `_common` `L1` hardware/runtime axiom or measurement gate is mounted automatically as part of the task foundation—either as a query result with `route: 'foundation_baseline'` or under a higher-scoring unit's `inherited_rules`—alongside the matched `L2` bottleneck/triage SOPs (`category: sop`). Treat every inherited rule as a condition-bound prerequisite, never let an `L2` SOP override an `L1` axiom or measurement gate, and never apply a unit whose premise is `condition_unknown`.
- **`L3` Hermes Mode (Heuristic Convergence & Skill Self-Evolution)**: Execute `L3` staged convergence workflows (`category: workflow`) as ordered stages, recording a structured probe per stage (stage goal, observed conditions, action/tool, `run_id`/`job_id`, measured signal, and judgment). When a stage reaches a verified milestone (`task_state: 'verified_milestone'`, i.e. verified evidence) or the task is genuinely `'completed'`, call `knowledge_distill` with the selected evidence; then call `knowledge_feedback` with the observed `unit_id` and **integer `revision`** (through the exact returned revision-bound `feedback_ref`) so successful convergence paths and repaired SOPs re-enter the P3 reuse flywheel. `task_state: 'in_flight'` is a zero-call no-op, and a host `Stop` event is never task completion.
- **`L4` RSI Mode (Recursive Self-Improvement / De-biased Exploration)**: If the routine `L3` workflow **stalls after 2 attempts**, escalate to `L4` RSI mode. Strip `L3` routine workflow bias from the candidate-generation context and keep only `Goal + L1 foundation + L2 bottleneck data + L4 mutators + experiment-ledger.jsonl conditional_avoid`. Generate candidates as orthogonal `L4` mutators (`category: mutator`) and run parallel CPU compile (`npu_count=0`) followed by serial exclusive physical-NPU timing (`devices=[0]`); never time two candidates concurrently on one physical NPU (or one A3 dual-Die package). Enforce **Gate 1–4**: `OracleFreezer` (freeze the goal/acceptance oracle), `MeasurementGuard` (synchronized, valid measurement window), `AblationGate` (baseline-bound verified final-combination ablation), and `Distill/Refute` (a supported or refuted judgment, never an unverified success). Append every `supported`/`refuted` judgment—including its `conditional_avoid`—to `experiment-ledger.jsonl`, and update `PROGRESS.md` (goal, verified baseline and best candidate, in-flight runs, next minimal experiment, retained avoid rules) before the next round. When a candidate survives Gate 1–4, distill it and return to `L3` execution.
